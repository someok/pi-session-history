## Problem Statement

用户在 pi 中恢复历史会话时，仅凭标题、时间以及原生消息总数，难以判断某个会话讨论到了哪里、实际使用了哪个模型，以及是否值得继续打开。尤其当会话未命名、标题相似、期间切换过模型，或最后用户消息包含较长需求和技能注入内容时，用户需要反复进入会话才能辨认目标。

用户希望保留熟悉的原生会话选择流程，在列表中直接看到准确的消息数和最后回复模型，并按需查看最后用户消息，而不是替换已有工作流或让模型生成额外摘要。

## Solution

提供独立 pi 扩展命令 `/history`，以 pi 1.1.0 的原生会话选择器为行为基线，保留原生 `/resume` 和启动时的 `pi --resume`。

每条会话默认显示两行：第一行保留原生标题、时间及相关识别信息；第二行显示整个会话历史的 user + assistant 消息数、最后一条 assistant 消息的 model 和 provider。

列表中按 `→` 展开最后用户消息的可读预览，按 `←` 收起；允许多条同时展开。消息预览最多显示 6 个终端显示行，将已识别的技能注入内容简化为技能名称，并以数量提示表示图片。按 `Ctrl+O` 打开同样内容口径的可滚动消息全文视图，按 `Esc` 返回且保留列表状态。列表中的 `Enter` 始终用于恢复会话。

搜索、范围切换、排序、筛选、重命名、删除和恢复行为对齐原生基线，明确排除本文指定的消息数、布局及新增按键差异。列表采用渐进加载，可见项优先；所有处理在本地完成，不调用模型、不上传内容。

## User Stories

1. 作为 pi 用户，我希望通过独立的 `/history` 打开增强会话选择器，以便无需改变原有恢复会话入口就能使用更多信息。
2. 作为 pi 用户，我希望原生 `/resume` 和 `pi --resume` 保持原样，以便随时使用原生体验作为替代。
3. 作为浏览历史会话的用户，我希望第一行沿用原生标题和未命名会话回退规则，以便继续凭熟悉的名称识别会话。
4. 作为浏览历史会话的用户，我希望看到与原生一致的活动时间及相对时间格式，以便判断会话最近何时使用过。
5. 作为浏览历史会话的用户，我希望保留选中高亮、当前会话标识和线程层级，以便知道正在操作哪一条及其关联关系。
6. 作为浏览历史会话的用户，我希望第二行集中展示消息数、model 和 provider，以便快速比较会话而不重复显示消息数。
7. 作为评估会话规模的用户，我希望消息数只统计 user 与 assistant，以便工具结果和 system 消息不会夸大对话规模。
8. 作为使用工具的用户，我希望仅包含工具调用的 assistant 消息仍被计数，以便统计口径始终按消息角色一致执行。
9. 作为使用会话分支的用户，我希望消息数包含整个会话的所有历史分支，以便了解完整会话历史而非仅恢复分支的规模。
10. 作为压缩过会话的用户，我希望消息数仍包含压缩前的历史，以便 compaction 不会被误解为历史消息消失。
11. 作为切换模型的用户，我希望看到最后一条 assistant 消息记录的模型，以便知道最后一次助手消息由谁处理，而不是看到后来尚未使用的模型。
12. 作为使用虚拟模型的用户，我希望显示助手消息所记录的实际模型及 provider，以便识别实际处理请求的模型，而不是仅看到路由器名称。
13. 作为经历错误或中止的用户，我希望仍看到最后一条 assistant 的模型信息，以便不会被更早的成功回复误导。
14. 作为浏览不完整会话的用户，我希望没有 assistant 和模型字段缺失分别有明确提示，以便区分尚未回复与元信息未知。
15. 作为浏览历史会话的用户，我希望按 `→` 原地展开最后用户消息，以便无需恢复会话即可了解最近的请求。
16. 作为使用分支的用户，我希望消息预览按整个会话的记录顺序选择最后 user message，以便与全历史的识别口径一致。
17. 作为搜索中的用户，我希望搜索框有文字时 `→` 和 `←` 仍用于展开与收起，以便预览操作不因查询状态改变。
18. 作为编辑搜索条件的用户，我希望仍可通过 `Ctrl+B`、`Ctrl+F` 等按键移动光标，以便新增预览快捷键不会使查询不可编辑。
19. 作为比较多个会话的用户，我希望多条会话可以同时展开，以便在列表中对照内容。
20. 作为比较多个会话的用户，我希望移动选中项不收起已展开的会话，以便保持比较上下文。
21. 作为切换排序或筛选条件的用户，我希望展开状态跟随会话身份保留，以便状态不会错误地落到另一个列表位置。
22. 作为再次打开选择器的用户，我希望默认恢复紧凑的收起状态，以便上次展开内容不会持续占用界面。
23. 作为阅读长需求的用户，我希望预览保留正文与换行并自动换行，以便内容易读且适应终端宽度。
24. 作为浏览多个会话的用户，我希望每条预览最多显示 6 个终端显示行，并提示截断和全文入口，以便长消息不会淹没整个列表。
25. 作为使用技能的用户，我希望已识别的技能注入正文简化为技能名称，以便优先看到自己提出的请求。
26. 作为阅读消息的用户，我希望无法识别的疑似技能块保留原文，以便不会因过度清理而丢失用户正文。
27. 作为发送图片的用户，我希望看到图片数量提示而不是图片数据，以便知道附件存在而不增加终端负担。
28. 作为最后仅发送图片的用户，我希望预览仍指向这一条消息，以便不会错误展示更早的文字请求。
29. 作为浏览空会话的用户，我希望没有 user message 时有明确提示，以便知道预览为空的原因。
30. 作为阅读完整需求的用户，我希望通过 `Ctrl+O` 直接打开选中会话的只读消息全文视图，以便不必先展开预览或恢复会话。
31. 作为阅读完整需求的用户，我希望全文沿用预览的正文、技能名称和附件提示口径，以便全文不会重新被技能注入内容淹没。
32. 作为阅读长消息的用户，我希望通过上下键和 PageUp/PageDown 滚动全文，以便查看超出屏幕的内容。
33. 作为返回列表的用户，我希望按 `Esc` 后保留搜索、选中项和展开状态，以便接着之前的位置浏览。
34. 作为准备继续工作的用户，我希望列表中的 `Enter` 始终恢复选中的会话，以便原生操作习惯保持稳定。
35. 作为查找会话的用户，我希望保留原生模糊搜索、精确短语、正则及搜索范围，以便已有查询习惯继续有效。
36. 作为跨项目工作的用户，我希望切换当前目录和全部会话范围，并保留自定义 session 目录语义，以便找到正确存储范围内的会话。
37. 作为浏览历史的用户，我希望保留线程、最近及相关性排序，以便按不同线索查找会话。
38. 作为整理会话的用户，我希望保留仅已命名筛选和路径显示，以便缩小范围并区分相似记录。
39. 作为整理会话的用户，我希望重命名会话时仍能正常编辑文本及使用左右键，以便预览快捷键不会干扰命名。
40. 作为清理会话的用户，我希望删除前必须确认且可以取消，以便避免误操作。
41. 作为正在工作的用户，我希望当前活动会话受到删除保护，以便不会在选择器中误删当前工作记录。
42. 作为清理会话的用户，我希望删除沿用原生优先废纸篓、不可用时永久删除的规则，以便增强入口与原生行为一致。
43. 作为自定义操作习惯的用户，我希望原有动作继续支持自定义快捷键，以便除了明确新增的按键规则外无需重新学习。
44. 作为小屏终端用户，我希望列表根据实际可用高度滚动并保持选中项可见，以便展开多条内容后仍能操作。
45. 作为使用中文或 emoji 的用户，我希望窄终端、缩放和主题变化后文字不越界错位，以便信息始终可读。
46. 作为普通或 fullscreen 模式用户，我希望两个模式下都能使用增强选择器，以便无需为功能切换显示模式。
47. 作为拥有大量会话的用户，我希望先看到可操作列表并渐进补齐信息，以便不必等待所有增强信息读取完成。
48. 作为等待加载的用户，我希望加载态与零条消息、未知模型和读取失败明确区分，以便不会将尚未加载误认为真实结果。
49. 作为浏览历史的用户，我希望单个会话增强信息读取失败不阻塞其他会话，以便仍能继续查找工作记录。
50. 作为关闭选择器的用户，我希望无用读取停止且迟到结果不重开或更新旧界面，以便退出操作立即生效。
51. 作为同时运行多个 pi 进程的用户，我希望重新打开选择器时重新校验会话信息，以便不持续看到过期缓存。
52. 作为重视隐私的用户，我希望消息预览不调用模型、不上传内容且不另行持久化正文，以便浏览历史不会引入额外的数据暴露。
53. 作为非交互模式用户，我希望扩展不在 RPC、JSON 或 print 模式启动终端界面，以便原有自动化工作流不受影响。

## Implementation Decisions

### Module 与公开 interface

- 新增一个负责增强会话选择流程的深 module，由扩展工厂注册 `/history`，通过 pi 的公开命令上下文与自定义 TUI 能力交互。
- 对外 interface 覆盖打开、接收用户输入、呈现结果、结束交互和请求恢复会话；会话发现、元信息读取、状态管理、预览转换和渲染属于 implementation，暂不把这些内部职责分别公开为测试 interface。
- 使用 pi 的宿主 adapter 处理终端交互和会话切换，遵循公开的生命周期、取消及切换契约；切换后不继续使用失效上下文。
- 不改变 session 存储 schema，不新增模型调用、遥测或持久化的预览副本。
- 不修改 pi 安装文件，不以同名命令注册透明覆盖原生 `/resume`。
- 原生选择器没有公开的自定义列表行渲染插槽；具体复用或移植方式留待 implementation 设计，不预设私有字段修改或运行时 monkey patch 为既定方案。

### 展示与数据契约

- 第一行沿用原生标题、首条消息回退、活动时间语义、时间格式、选中及当前会话样式、线程层级，以及相应模式下的目录和路径信息。
- 原生第一行消息数移除；第二行依次显示消息数、model、provider，消息数使用 `msgs` 标识。
- 消息数统计整个持久化会话历史中角色为 user 或 assistant 的消息，包括其他历史分支、压缩前记录及只有工具调用的 assistant 消息。
- 不计工具结果、system、直接 bash 执行、扩展自定义消息及其他角色；工具内部嵌套调用不额外增加消息数。
- 最后回复模型取整个历史按记录顺序最后一条 assistant 消息的 model/provider，不以时间戳重新排序，不取最后模型选择记录，也不限准备恢复的分支。
- 错误、中止的 assistant 记录仍参与计数及最后回复模型选择；不回退至更早的成功消息。
- 无 assistant 显示 `No assistant message`；最后 assistant 的 model/provider 字段缺失时，相应字段显示 `unknown`。

### 消息预览与全文契约

- 最后用户消息取整个历史按记录顺序最后一条 user message；不以最后非空文本替代，不把其他角色转换成 user 后选取。
- 保留正文和换行，按终端显示宽度换行；已识别的技能注入块转换为技能名称，图片转换为数量提示。
- 对无法识别的疑似技能块保留文本；只有技能或附件时，仍显示对应技能名称或附件提示。
- 无 user message 显示 `No user message`；最后 user 仅含图片时不回退。
- 原地预览最多展示 6 个终端显示行，超出时展示截断与全文入口提示。
- 消息全文视图使用同一可读内容口径，无 6 行上限，只读并支持滚动；不重新显示技能注入正文或图片数据。

### 交互状态契约

- 列表模式中 `→` 展开、`←` 收起；重复展开或收起不改变既有状态，也不隐式打开全文。
- 无论搜索框是否有文字，左右键都优先操作预览；搜索文本仍可通过 Ctrl+B、Ctrl+F 等按键编辑。
- 重命名模式保持正常文本编辑；删除确认模式优先遵循原生确认/取消流程，不允许预览按键绕过确认。
- 允许多项同时展开；展开状态以会话身份关联，移动选中项、排序、筛选及范围切换时保留，关闭选择器后重置。
- 列表 Ctrl+O 直接打开选中项全文，不要求先展开；全文上下键及 PageUp/PageDown 滚动，Esc 返回并保留原列表状态。
- 列表 Enter 恢复会话；恢复遵守宿主生命周期和取消结果，不能将取消当作成功切换。
- 按终端可用高度处理变高条目的可见范围与滚动，确保选中项可见，不固定照搬原生显示 10 条的布局。
- 界面提示沿用英文风格，并支持原生主题与终端宽度处理；文档及代码注释使用中文。

### 原生兼容契约

- 以 pi 1.1.0 为基线，支持普通 TUI 和 fullscreen；非 TUI 模式不启动自定义终端界面。
- 保留原生模糊、精确短语和正则搜索及匹配范围，不额外添加 model/provider 搜索语义。
- 保留当前目录/全部范围切换、原生自定义 session 目录语义、线程/最近/相关性排序、已命名筛选和路径显示。
- 保留重命名、分页、取消、恢复及已有动作的自定义快捷键支持，本文明确改变的按键规则除外。
- 删除需要确认，禁止删除当前活动会话；优先使用废纸篓，不可用时按原生行为永久删除。
- 消息数展示口径变化不得顺带改变搜索、排序或会话恢复逻辑。

### 加载与失败契约

- 渐进显示列表，尽早允许搜索和选择；优先读取可见项的增强信息，而非等待所有元信息完成后再显示。
- 未就绪明确显示加载态，不能暂用 `0`、无消息或 `unknown` 冒充最终结果。
- 单条增强信息读取失败只标记该项失败，其他项仍可操作。
- 关闭后停止无用读取，迟到异步结果不能再更新已关闭界面。
- 重新打开时重新校验会话信息，避免永久陈旧缓存；不进行实时文件监听。
- 不另行持久化预览正文，不上传会话内容，也不调用模型生成或清理预览。

## Testing Decisions

### 已确认的主要 seam

用户已确认以增强 module 与 pi 宿主之间的公开 interface 为一个主要测试 seam：从真实扩展工厂的命令注册及 `/history` 调用流程进入，输入 session 数据和用户操作，观察用户可见输出与宿主行为。

- 使用隔离临时目录中的真实 session JSONL，保留真实会话读取、消息数计算、最后回复模型提取、技能内容处理、搜索排序、展开状态和布局逻辑。
- 以受控 pi 宿主 adapter 提供命令上下文、终端尺寸、按键和可观察的渲染输出，捕获会话切换请求及取消结果。
- 环境故障、加载延迟和完成时序可控；只在外部依赖需要替换时使用 adapter，不将内部步骤逐个 mock。
- 重命名及删除验证仅作用于测试临时数据；废纸篓调用使用受控替身，避免触碰用户真实历史或真实废纸篓。
- 主测试通过同一个 seam 覆盖整条行为链，不为解析器、缓存、列表和全文视图分别规定彼此耦合的公共测试 interface。

### 好测试的判据

- 断言外部行为：显示内容及显示行数、选中与展开效果、搜索结果、返回后的状态、变更后的临时文件、恢复目标和取消结果。
- 不断言私有字段、缓存结构、内部函数调用次数或类的拆分方式；implementation 重构而用户行为不变时，测试仍应通过。
- 测试时间和异步推进可控，避免依靠不稳定的固定 sleep；性能相关验收关注渐进可操作、可见项优先及关闭后不更新，不虚构尚未测量的毫秒 SLA。
- 对关键文字、布局宽度和交互进行语义断言，避免仅依赖难维护的整屏快照；需要快照时使用确定的尺寸、时间及主题。

### 待覆盖的验收矩阵

| 测试组 | 必须覆盖的外部行为 |
| --- | --- |
| 消息数 | 混合角色、工具调用型 assistant、嵌套工具调用、多个历史分支、compaction 前后；只计全历史 user + assistant |
| 最后回复模型 | A 回复后仅选择 B 仍显示 A；虚拟模型显示记录中的实际模型；错误/中止不回退；无 assistant 与缺字段分别提示 |
| 最后用户消息 | 全历史记录顺序、仅图片的最后消息、无 user、技能加正文、技能加附件、只有技能、无法识别的疑似技能块 |
| 默认展示 | 第一行沿用原生语义和样式，第二行字段顺序正确且消息数不重复 |
| 预览按键 | 空/非空搜索时左右键展开收起，重复操作幂等，替代光标编辑可用，重命名和删除确认不受干扰 |
| 展开状态 | 多项同时展开，移动/排序/筛选/范围切换后仍关联正确会话，关闭后清空 |
| 预览与全文 | 换行后最多 6 行及截断提示，直接 Ctrl+O、全文滚动、Esc 返回保留状态，列表 Enter 仍请求恢复 |
| 原生查询 | 模糊/短语/正则及原有匹配范围、三种排序、线程关系、范围切换、已命名筛选、自定义 session 目录 |
| 原生管理 | 路径显示、重命名、分页、取消、自定义快捷键、删除确认/取消、当前会话保护、废纸篓成功及永久删除回退 |
| 会话切换 | 正确目标、宿主取消、不使用已失效上下文继续进行会话相关操作 |
| 渐进加载 | 列表先可用、增强信息后补齐、可见项优先、加载态不同于空值、单条失败隔离、关闭后迟到结果无效 |
| 外部变化 | 修改临时会话后重新打开能校验到变化，不依赖实时监听 |
| 终端适配 | 中文、emoji、窄宽度、小高度、多项展开、缩放、主题变化，输出不越界且选中项可见 |
| 隔离与隐私 | 非 TUI 不启动界面，浏览不调用模型、不上传、不另行保存预览正文，不修改 pi 安装 |

## Out of Scope

- 替换或重定向原生 `/resume`、启动时的 `pi --resume`。
- 修改 pi 安装文件，或承诺无维护地自动跟随未来原生选择器变化。
- 首版兼容所有历史或未来 pi 版本。
- RPC 客户端中的图形化选择器及非 TUI 的交互界面。
- 自动生成会话摘要、图片渲染、编辑消息全文、显示图片数据或完整技能注入正文。
- 添加 model/provider 搜索筛选、统计面板、遥测或实时文件监听。
- 改变消息存储 schema、把消息数改为轮数、只统计当前分支或仅统计 compaction 后上下文。
- 本次规格发布过程中实施扩展、发布 npm 包、提交或推送 Git 变更。

## Further Notes

- 产品行为、边界规则和测试 seam 均已由用户确认，可直接作为实现规格；无需再次产品分诊。
- 领域术语采用项目术语表中的消息数、最后回复模型、最后用户消息、消息预览及消息全文视图。
